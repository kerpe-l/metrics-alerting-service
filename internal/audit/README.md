# internal/audit

Аудит запросов через паттерн «Наблюдатель».

## Назначение

Сервер после успешной обработки метрик формирует событие [`Event`](event.go) и
рассылает его всем зарегистрированным приёмникам. Приёмники реализуют интерфейс
[`Observer`](observer.go).

## Формат события

```json
{
  "ts": 1715600000,
  "metrics": ["Alloc", "Frees"],
  "ip_address": "192.168.0.42"
}
```

## Ключевые решения

- **Асинхронная доставка**: `Publisher.Publish` возвращает управление сразу и не
  задерживает HTTP-ответ клиенту. На каждого наблюдателя порождается отдельная
  горутина, ошибки логируются и не влияют на других.
- **Graceful shutdown**: `Publisher.Close(ctx)` ждёт завершения всех уже
  запущенных горутин рассылки. Если переданный контекст истекает раньше,
  внутренний контекст наблюдателей отменяется, и `Close` возвращает `ctx.Err()`.
- **Регистрация — на старте.** `Register` не синхронизирован: подразумевается, что наблюдатели добавляются до начала приёма запросов.

Реализации приёмников — в этом же пакете: `FileSink` (запись JSON-строкой в
файл), `HTTPSink` (POST на удалённый URL).
