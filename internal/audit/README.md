# internal/audit

Аудит запросов через паттерн «Наблюдатель».

## Назначение

Сервер после успешной обработки метрик формирует событие [`Event`](event.go) и
рассылает его всем зарегистрированным приёмникам. Приёмники реализуют интерфейс
[`Observer`](observer.go).

## Формат события

```json
{
  "ts": 1715600000,
  "metrics": ["Alloc", "Frees"],
  "ip_address": "192.168.0.42"
}
```

## Ключевые решения

- **Наблюдатели — в конструкторе.** `NewPublisher(observers...)` фиксирует набор
  приёмников при создании; слайс далее не меняется, поэтому синхронизация
  доступа не нужна. Метода `Register` нет.
- **Воркер на наблюдателя с ограниченной очередью.** Для каждого наблюдателя —
  отдельная горутина и буфер ёмкости `bufferSize`. `Publisher.Publish`
  раскладывает событие по очередям неблокирующе и сразу возвращает управление,
  не задерживая HTTP-ответ. Если очередь наблюдателя переполнена (медленный
  приёмник при быстром потоке событий), событие для него **отбрасывается** с
  записью ошибки в лог — число горутин ограничено и не растёт бесконтрольно.
  Ошибки наблюдателей логируются и не влияют на других.
- **Graceful shutdown**: `Publisher.Close(ctx)` закрывает очереди и ждёт, пока
  воркеры обработают буферизированные события. Если переданный контекст
  истекает раньше, внутренний контекст наблюдателей отменяется. Затем
  закрываются наблюдатели, реализующие `io.Closer` (например, `FileSink`);
  ошибки закрытия объединяются через `errors.Join` и не мешают друг другу.

Реализации приёмников — в этом же пакете: `FileSink` (запись JSON-строкой в
файл), `HTTPSink` (POST на удалённый URL).
