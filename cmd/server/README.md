# cmd/server

Сервер сбора метрик. Принимает метрики от агентов по HTTP и хранит их в памяти с возможностью периодического сохранения на диск.

## Сборка

```bash
go build -o server ./cmd/server
```

### Со сведениями о сборке

Версия, дата и коммит подставляются линкером и печатаются в stdout при старте
(пустые значения выводятся как `N/A`):

```bash
go build -ldflags "\
  -X main.buildVersion=v1.2.3 \
  -X 'main.buildDate=$(date +%Y-%m-%d)' \
  -X main.buildCommit=$(git rev-parse --short HEAD)" \
  -o server ./cmd/server
```

## Запуск

```bash
./server [флаги]
```

## Флаги и переменные окружения

| Флаг | Переменная окружения | По умолчанию | Описание |
|------|----------------------|--------------|----------|
| `-a` | `ADDRESS` | `localhost:8080` | Адрес и порт сервера |
| `-i` | `STORE_INTERVAL` | `300` | Интервал сохранения метрик на диск (сек). `0` — синхронная запись после каждого обновления |
| `-f` | `FILE_STORAGE_PATH` | `/tmp/metrics-db.json` | Путь к файлу для хранения метрик |
| `-r` | `RESTORE` | `true` | Загружать ранее сохранённые метрики при старте |
| `-d` | `DATABASE_DSN` | `""` | Строка подключения к PostgreSQL |
| `-k` | `KEY` | `""` | Ключ для подписи данных (HMAC-SHA256) |
| `--audit-file` | `AUDIT_FILE` | `""` | Путь к файлу аудита (пусто — файловый аудит отключён) |
| `--audit-url` | `AUDIT_URL` | `""` | URL приёмника аудита (пусто — удалённый аудит отключён) |

Если задана переменная окружения — используется она. Иначе — значение флага. Иначе — значение по умолчанию.

## Примеры

Стандартный запуск (сохранение каждые 5 минут, восстановление при старте):

```bash
./server
```

Синхронная запись (каждое обновление сразу пишется в файл):

```bash
./server -i 0
```

Свой файл, без восстановления, интервал 30 секунд:

```bash
./server -i 30 -f ./my-metrics.json -r false
```

С PostgreSQL:

```bash
./server -d "postgres://user:pass@localhost:5432/metrics"
```

Через переменные окружения:

```bash
STORE_INTERVAL=60 FILE_STORAGE_PATH=./data.json RESTORE=true ./server
```

Запуск с подписью данных:

```bash
./server -k=mysecretkey
```

## Аудит запросов

Сервер реализует паттерн «Наблюдатель» для журналирования событий приёма метрик.
После успешной обработки запроса событие рассылается всем сконфигурированным
приёмникам:

- `--audit-file` / `AUDIT_FILE` — путь к файлу. Каждое событие дописывается
  отдельной JSON-строкой.
- `--audit-url` / `AUDIT_URL` — URL удалённого приёмника. Событие отправляется
  методом `POST` с телом `application/json`.

Если ни один параметр не задан, аудит отключён. Можно включать оба приёмника
одновременно — событие будет отправлено в каждый.

Формат события:

```json
{ "ts": 1715600000, "metrics": ["Alloc", "Frees"], "ip_address": "192.168.0.42" }
```

Пример запуска с обоими приёмниками:

```bash
./server --audit-file=./audit.log --audit-url=http://localhost:9000/audit
```

Подробнее о реализации — в [internal/audit](../../internal/audit/README.md).

## Подпись данных (HMAC-SHA256)

При указании ключа (`-k` или `KEY`) сервер проверяет HMAC-SHA256 подпись входящих запросов (заголовок `HashSHA256`) и подписывает тела ответов тем же заголовком. При несовпадении хеша запрос отклоняется с кодом `400 Bad Request`. Ключ должен совпадать с ключом агента.
